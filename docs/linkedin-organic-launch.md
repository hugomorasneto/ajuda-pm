## Post 02 — Antes e depois

Exemplo simples de como uma demanda solta pode melhorar antes de chegar ao time.

Antes:
"Melhorar onboarding para empresas e validar domínio no cadastro."

Melhor, mas ainda incompleto:
"Como pessoa responsável pelo cadastro de uma empresa, quero validar o domínio corporativo durante o onboarding para concluir o registro com menos retrabalho."

Critérios que já ajudam a conversa:

- permitir avanço apenas quando o domínio estiver em formato válido;
- exibir mensagem clara quando o domínio não puder ser aceito;
- preservar os dados preenchidos quando houver erro;
- confirmar exceções para domínios parceiros.

## Post 03 — Critérios de aceite

Checklist rápido para revisar critérios de aceite antes de levar uma user story ao refinamento:

- O comportamento esperado está claro?
- Existe cenário positivo e cenário de erro?
- A mensagem para o usuário foi definida?
- As exceções importantes aparecem no texto?
- Dev e QA conseguem validar sem depender de explicação verbal?
- O critério evita termos vagos como "rápido", "intuitivo" ou "melhor" sem medida?

Critério de aceite bom não é burocracia.
É uma forma de reduzir retrabalho e alinhar produto, desenvolvimento e QA antes da entrega começar.
